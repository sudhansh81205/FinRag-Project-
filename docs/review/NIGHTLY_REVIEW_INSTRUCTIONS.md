## Complete daily report

Produce a dated report even when no code changed, explicitly saying so. Include:

1. Snapshot/cutoff metadata, contributor/publication attribution and merged versus submitted state.
2. Dated sole owner, planned deliverable/estimated hours and actual verified work with source links. Missing submission is not proof of no private effort.
3. Cumulative R1-R8/R10-R13 acceptance and milestone position. R9 remains unscheduledPhase 2. Do not infer completion percentage without explicit acceptance denominator.
4. Prioritized findings with exact immutable source/line links, observed consequence, minimal repair, requirement/stage/control, confidence and success/failure checks. Separate code defects from missing features, runtime assets, independent labels and planned work.
5. Fixed/open/regressed finding history and meaningful tests actually run, reused or unavailable. Unchanged exact-SHA evidence can be reused explicitly; do not manufacture fresh tests.
6. Next scheduled date and sole owner from published schedule, estimate, prerequisites, ordered work, acceptance, verified command forms and missing manual inputs. No off-day background assignments.
7. Actual stack/configuration/versions or unknowns, and useful official version-sensitive references. Config files do not prove model availability.
8. Copy-ready implementation and verification/handoff prompts tailored to that owner, using MASTER_PROMPT as base.
9. Improvement bridge linking current defect to next bounded action, expected behavior and proof, plus deferred mandatory scope and deadline/capacity risks.
10. Actual artifact/delivery status and evidence. Identify review model only when reliably exposed; otherwise exact variant unknown, separate from FinRAG's inference model. A prompt cannot pin runtime model selection.
