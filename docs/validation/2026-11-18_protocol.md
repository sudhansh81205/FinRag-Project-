# PRD-aligned development validation protocol

This study validates the current18-filing application and one retrieval component comparison. It does **not** replace or certify the original final A-G study, official benchmark results, RAGAS, the separate Llama comparison, original-chart acceptance or the independent fifty-output audit. No PRD scope was removed. Study references and questions were frozen before new execution in `output/validation-20261118-v1/manifest.json` and `cases.json`.

## Questions being tested

1. For supported consolidated annual metrics, does the application return the source-derived value with the correct units, selected filing, requested period and included cited operands?
2. Does it refuse mismatched company/year, quarterly/live/prediction and unsupported comparison requests, and avoid substituting consolidated totals for narrower component questions?
3. With canonical cell representation, BGE/exact FAISS, original question, explicit filing/scope eligibility and candidate depth fixed, does adding BM25/RRF60 improve required-operand retrieval compared with dense-only ranking?

The third question tests the retrieval mechanism added by the PRD's C-to-D transition. It is a **retrieval-only development component comparison**, not complete C/D answer generation or a full A-G experiment. It does not measure the effects of chunking, reranking, routing, captions or model choice.

## Frozen cases and reference provenance

-72numerical requests:18filings times revenue, net income, gross margin and adjacent-year revenue growth. One known unanswerable Oracle gross-margin case remains in the72-request ledger and has a separately reported expected-refusal outcome. The other71requests have numerical reference values.
-12robustness requests:8explicit scope/company/year/unsupported-request guards,2component-versus-total questions,1relative-percent-versus-percentage-point question and1compound-metric question. All were specified before this new execution, including anticipated failures. No case is removed for failing.
-6risk narrative requests:Apple2025,Microsoft2025,NVIDIA2024,IBM2024,Cisco2024,Oracle2024. Actual output and exact included context are retained. Semantic quality remains unreviewed until a genuine reviewer uses the supplied rubric. Structural citation agreement is not semantic faithfulness.

The development question bank existed before this study and was used during implementation. This is **not a held-out test**. References reuse parsed financial metric identities and thus share interpretation assumptions with the application. To strengthen reproducibility, a separate original-source reader checks71unique referenced inline operands: exact locator, metric/context, displayed value, scale and original end date. Numerical expectations are then recomputed from those original values using explicit arithmetic rather than the application planner. IBM's incorporated exhibit explicitly binds its contexts from the main10-K. This is automated source corroboration, not independent human approval.

Reference answers, labels and operand groups are never included in the HTTP question payload or retrieval query. The original natural-language question is used unchanged for the retrieval comparison; no named-metric query expansion or exact typed lookup is applied there. Numerical application validation deliberately measures the actual interactive typed-calculator route; it is not evidence of LLM arithmetic accuracy.

## Metrics and definitions

| Metric | PRD mapping | Definition and denominator |
| --- | --- | --- |
| Numerical source-reference agreement | R5/R7, numerical tolerance | Among71labelled numerical cases, successful result within1%relative error AND correct unit, requested period, accession and cited required operands. Show numerator/denominator, not only a percentage. |
| Expected refusal | R5/R6 | Oracle's missing aggregate operands are reported as1explicit unanswerable request, not omitted from the72requests. |
| Robustness pass rate | R5/R6/R12 |12predeclared adversarial cases; correct refusal/clarification or complete supported result as specified. Fluency and a valid total citation cannot excuse the wrong question intent. |
| Recall@5/@10 | R7/R10 | Fraction of required source-operand groups represented in the top5/top10. Same-valued repeated occurrences with identical metric/scope/period/unit are interchangeable members of one group. |
| Complete-operand coverage@5/@10 | R7/R12 | Fraction of the71labelled retrieval questions for which every required group appears by rankk. A single revenue hit is insufficient for a revenue-growth or margin calculation. |
| MRR@10 | R7 | Reciprocal rank of first relevant operand,0when none appears in top10. This is distinct from finding all operands. |
| Local latency | R7/R13 | Median andp95of one actual local HTTP request per case; numerical, robustness and narrative groups reported separately. Warm prepared runtime; no cold-start, Vercel or general load/capacity claim. |
| Narrative structural citation checks | R6/R7 | Returned evidence IDs equal included context IDs and match selected accession. This cannot prove each claim true. Manual semantic fields remain blank. |
| Uncertainty | R7/R12 | Seed42;10,000bootstrapresamples of whole filings, preserving related questions within each sampled filing. Dense/hybrid effects use paired per-case differences and the same sampled filing groups. |

All chosen numerical references are nonzero; zero-gold scoring is therefore **not tested** in this subset. Unit or period errors fail even when the number matches. Intervals describe variation within this selected development set, not generalisation to all unseen financial questions. A100%observed result can yield a100%-100%bootstrap interval; that does not imply certainty or external validity.

## Retrieval controls

The same15,411-record canonicalCstore, pinned BAAI/bge-base-en-v1.5 revision,768normalized dimensions and exact FAISS are used. Both methods receive identical explicit ticker/accession/consolidated/table-cell filters. All comparative years in that filing remain candidate cells, so ranking must select the correct period. Dense retrieves10; BM25retrieves10; hybrid uses canonical reciprocal-rank fusionk60and evaluates its top10. The exact same once-computed query vector is reused in both methods. No cross-encoder, routing, chart descriptions, parent injection, prompt or generator comparison is claimed. These controls isolate table-cell lexical fusion only.

Embedding batch time is reported separately. Dense-search time and added BM25/RRFtime do not include model-load time or generation, and the batch embedding cost is not misrepresented as per-user request latency. No retrieval/model job runs concurrently with the measured HTTP series.

## Reproduction and integrity

From a prepared checkout with the existing verified model/index corpus, choose a new output directory for a fresh reproduction:

```sh
.venv/bin/python scripts/evaluate_workspace.py prepare --output output/validation-reproduction
.venv/bin/python scripts/evaluate_workspace.py http --output output/validation-reproduction
.venv/bin/python scripts/evaluate_workspace.py retrieval --output output/validation-reproduction
.venv/bin/python scripts/evaluate_workspace.py summarize --output output/validation-reproduction
```

Use a new `--output` directory for a changed study. Preparation refuses an existing manifest. Frozen input/source/code hashes are verified on subsequent commands. HTTPexecution saves a row after every completed request and can resume matching question inputs; network/model failures are recorded, not silently retried into successes. Keep private API credentials outside results. The recorded source commit is4d168800; new evaluation tooling is identified by its frozen file hashes. The serving application's bytes are the previously deployed final implementation; this development evaluation does not change them.

No automated process may fill a human reviewer identity, approve its own labels, upgrade this subset to full-study acceptance or claim an official benchmark score. Report measured failures and use them to limit product claims. If the app is subsequently repaired, retain this baseline and create a new revision/run rather than overwriting outcomes.

### Disclosed execution amendment

After the90HTTPrequests, the first retrieval attempt stopped before saving any rankings: the BM25streamAPIrejects an explicit`type`filter and selects its type through stream budgets. The runner was corrected to pass the same ticker/accession/scope filters with textdepth0/tabledepth10, preserving the declared table-cell pool. Original cases, references and all90HTTProws were copied byte-for-byte into `output/validation-20261118-v2`; the original pre-execution manifest/runner and an analysis amendment with old/new hashes are retained. No question, outcome, scoring rule, source universe or retrieval hyperparameter was changed. The final results report includes that amendment. This does not change the application under evaluation.

For latency interpretation, “warm prepared runtime” in the runner means services were already running. Model residency/cold state and unrelated machine load were not controlled; only local observed elapsed times are defensible.
