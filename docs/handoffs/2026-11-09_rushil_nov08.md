## What is implemented

- `src/llm/client.py`, `ollama_profile.py`, `configs/gemma3-4b.json`: real Gemma 3
  4B through Ollama, exact installed manifest digest and quantization, before/after
  identity checks, explicit errors, bounded options, structured image input and
  rejection of output-limit truncation. No automatic model/provider/mock fallback.
  Default YAML and `.env.example` now select this profile. An existing private
  `.env` still takes precedence and must be explicitly reviewed when reproducing.
- `src/llm/typed_calculator.py`: a declarative operation tree with at most 31
  nodes/depth 7. Leaves must resolve to actual included canonical table cells.
  Decimal precision 28; only add, subtract, multiply (ratio times quantity), divide,
  ratio_percent, change and percent_change. No constants, Python or function calls.
  The result retains the operation tree, expression, raw/normalized operands,
  evidence IDs, exact result, units, rule premises/outcomes and policy notes.
- Typed checks: source content hash, complete fact identity, displayed versus
  normalized value/scale, issuer, scope, unit/currency, explicit requested periods,
  same-period operations, comparable adjacent annual periods/metric, nonzero
  denominator. Positive prior permits ordinary growth; zero prior refuses; negative
  prior returns absolute change with an explanation. Unsupported dimensional
  products and further arithmetic on percentages refuse explicitly.
- `src/llm/calculation_planner.py`: the pinned real model proposes a JSON expression
  using included IDs. The caller fixes issuer/scope/periods; the model cannot insert
  numbers or override those constraints. Validation always precedes explanation.
  This supports bounded operations, not arbitrary natural-language math semantics.
- `FinRAGEngine.answer_financial_question`: accepts `calculation_plan` or
  `calculation_request`. It first selects complete context, then validates the
  program against that exact selection. A missing/excluded operand stops financial
  generation. The validated program/result are returned and passed to the model
  for explanation. The primary numerical `answer` is deterministically rendered
  from the verified calculator. Raw `model_explanation` is saved separately for
  review; it cannot replace the authoritative result or arithmetic program.
- `src/charts/caption.py`: original-image/report/hash/locator binding, vision model
  fingerprint, bounded structured caption, title/axes/units/periods/series, explicit
  unknowns. Generated provenance is retained. Point-value extraction is disabled
  by default until a caller has verified actual printed point labels. Structured
  JSON does not establish visual correctness: source review remains required.
- Chart descriptions are opt-in (`enable_chart_descriptions=True`), source-linked,
  reviewed and subject to the same whole-object character safety budget before
  entering a prompt. Candidates marked pending are excluded. This hook does not
  claim the absent final A-F retrieval/index/routing implementation exists.
- `data/charts/apple-2021-candidate-questions.json`: 15 authored, visually checked
  development candidates on one original Apple chart; label basis and source
  identity retained. Independent review is pending. All one image stays dev;
  `src/charts/questions.py` rejects image/source/duplicate-group split leakage.
- `configs/llama32-comparison.json`: separate unexecuted Llama 3.2 3B text-only
  comparison configuration. It does not substitute for the pinned Gemma candidate.

## Reproduce

Use Python 3.12+ and the repository's pinned dependencies, then start local Ollama
on loopback and install `gemma3:4b` from the official library. Model weights are
local cache, not Git artifacts. Verify installed digest equals
`68ceab7e468a31c988b44d5a4984a0e21f58c4f7158c6ce29c1804babac38df7`.
Do not silently update a moving tag if its digest differs.

```sh
python -m pip install -r requirements-dev.txt
ollama pull gemma3:4b
python scripts/prepare_evidence.py
python -m pytest -q
ruff check .
python scripts/run_rushil_checks.py --output output/rushil-nov08
python app.py --check
```

The real smoke uses already selected canonical evidence, not a replacement search
algorithm, BGE retrieval score or held-out evaluation. It saves real generation,
model-proposed and supplied calculation trees, source growth, missing operand/model,
wrong digest, captions, chart counts, source/config hashes, hardware and timings.
A failed model/caption check returns a nonzero exit. Chart scope remains unmet even
when all implementation smoke checks pass.

A caller can request automatic bounded planning after retrieval:

```python
result = engine.answer_financial_question(
    "What was Apple's fiscal 2021 gross margin percentage?",
    calculation_request={
        "issuer": "Apple Inc.", "scope": "consolidated",
        "periods": [{"kind": "duration", "start": "2020-09-27", "end": "2021-09-25"}],
    },
)
```

Explicit issuer/period filters are essential; the model cannot infer authoritative
request constraints from an arbitrary ambiguous question. An explicit tree can be
passed using the same structure plus `expression`, as `calculation_plan`.

## Connection to Course Concepts

**KR&R (facts, predicates, inference):** cited cells instantiate issuer/metric/
period/scope/unit/value facts. Deterministic predicates establish whether an
operation is allowed. The operation's result is a conclusion with a trace. A
missing operand or zero denominator prevents a conclusion. This is a small rule
system, not a general theorem prover or a trained financial expert.

**DL for NLP:** a pretrained Gemma transformer proposes a bounded program and
explains its validated result. The model's generated program is untrusted input;
the calculator validates and executes it. No fine-tuning or training is claimed.

**Computer vision:** pretrained multimodal Gemma describes an original report
image; hash/locator link it back to the source. Incorrect units/guessed values are
failure modes, so unclear point values stay unknown and labels need independent
review. Structured syntax is insufficient evidence of factual correctness.

**Ethics/reliability:** explicit AI assistance in implementation, source checks,
unknown values, retained failures, honest coverage and no mock success. Git commits
use the user's repository-local author identity; disclosure is in project records.

Viva example: sales 365,817 and cost 212,981 (USD millions) imply gross profit
152,836 million, then `152836 / 365817 * 100 = 41.779359625...%`, rounded **41.78%**.
Every operand carries a cited cell ID. Comparing a different issuer/segment/period
or dividing by zero fails a predicate and does not reach financial generation.
BGE/BM25/RRF are retrieval methods, not A*, minimax, game theory or multi-agent AI.
