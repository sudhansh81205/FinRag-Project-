## Source evidence and scope

The corpus inventory has five Apple and five Microsoft 10-Ks plus eight technology issuers. The original SEC responses for the 17 additional filings and IBM's incorporated SEC exhibit are archived as gzip files in `data/source/corpus`. Each uncompressed byte stream is pinned in `data/corpus_html_profiles.json`. The Apple 2021 historical source and audit follow their original path. The coverage JSON binds each candidate package and index generation to its actual source bytes. In IBM's case, statement values come from the linked exhibit while inline XBRL contexts resolve against the filed 10-K.

The parser checks issuer, CIK, form, fiscal year and report end against SEC DEI facts, then reads visible Item 1A, 7 and 8 narrative blocks and three pinned primary statement grids. Intel uses checked section bounds based on its nonstandard organization and cross-reference index. Table cells retain the original displayed value, row and column, typed XBRL period/unit/scale, parent and locator. The parser checks the issuer, comparative year and displayed/tagged magnitudes. Opening cash balances have explicit instant-period handling. Questionable numbers stay visible in the parent grid and are reported if they fail typed extraction.

On four additional Apple PDFs, Docling matched the total net sales row to the original HTML cells and pdfplumber independently matched the word, row and year coordinates. The PDF evidence corroborates the HTML record IDs. Statement coverage focuses on income, balance sheet and cash flow, with notes and other statement layouts subject to supported extraction. The earlier Microsoft 2022 and Oracle 2024 PDF rendition checks remain unresolved. Their exact SEC HTML is now recovered and parsed.

## Matched representations and reproduction

A uses overlapping 1,000-character chunks over consecutive narrative blocks within each eligible section and source, with 200 characters of target overlap. B and C use the same section-aware block passages. A and B share the same flattened Markdown table passages, grouped by exact value period, scope and unit so each passage has an unambiguous eligibility predicate. Their source cell IDs map to C's self-describing cells. C keeps the complete parent tables separately for expansion. All three use the same pinned 768-dimensional L2-normalized BGE embeddings and exact FAISS inner product. Shared passage texts get the same vectors from one inference batch.

```powershell
python -m pip install -r requirements-dev.txt -r requirements-index.txt
python scripts/prepare_evidence.py
python scripts/verify_canonical_data.py
python scripts/build_index.py --download-model
python scripts/build_corpus_candidates.py --build
python -m pip install pdfplumber==0.11.9

```

Use `--model-cache` to point at already cached BGE weights. The index builder reads the archived SEC HTML offline. The PDF verifier uses the pinned rendition URLs or local copies. Its package input defaults to `output/nov13`, which also contains the coverage ledger and separate A/B/C stores. Repeat builds check the same immutable package, manifests and ordered IDs before reusing a generation. For a new source or changed representation, choose a fresh output directory.

For a byte-level rebuild on the same Windows CPU and runtime, use `OMP_NUM_THREADS=6` and `MKL_NUM_THREADS=6` before running the build. The archived Apple 2024 test produced identical package and A/B/C generation hashes with those settings. A three-thread rebuild preserved all evidence and IDs, with a maximum vector coordinate difference of `2.84e-7`. Record runtime and thread settings before comparing exact hashes across machines.

For A and B the dense adapter is `DenseRetriever(ExactStore(output / variant), encoder, table_kind="financial_table")`. It returns cross-stream cosine order. For C use the existing `HybridRRFRetriever` configured for C with the C store, matching BM25 records and parent map. The review stores can be queried directly with `scripts/query_index.py --store output/nov13/C`. These are review candidates awaiting the independent gate.
