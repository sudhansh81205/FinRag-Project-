## 4. Viva Defense Key Positions

1. **Why is the release designated "Transparently Partial"?**
   *Answer*: Academic honesty is non-negotiable. Pavan's November 16 audit confirmed that the development test environment lacked live GPU hardware and Ollama daemon instances. Fabricating numbers or presenting mock fixtures as authentic benchmarks would violate scientific integrity. The software architecture, scoring math, AST calculator, and test harness are complete and fully passing (459 tests).
2. **How does FinRAG prevent arithmetic hallucinations?**
   *Answer*: FinRAG completely disallows raw LLM arithmetic and arbitrary `eval()`. Numerical reasoning is parsed into an AST tree with an allowlisted operation set (`add`, `subtract`, `multiply`, `divide`, `ratio_percent`, `change`, `percent_change`), max depth 7, max nodes 31, and every leaf must bind to a strictly validated `evidence_id` present in the retrieved context.
3. **How does request binding work?**
   *Answer*: In `src/application.py`, requests are bound to issuer and period. If a user asks for Microsoft FY2022, FinRAG will never return Apple FY2021 numbers, even if Apple numbers are retrieved with high similarity. Mismatches trigger a safe, typed refusal.
