# Ujjwal Day 5 environment and contract check

Date: November 3, 2026. Planned allocation: eight hours. Actual human time is
not inferred from this report.

## Scope

This checkpoint implements only the unified PRD task: verify resources and
handoff contracts before the BGE/FAISS build. It does not build an index, add
retrieval, expand the corpus, or claim model readiness.

Run from the repository root:

```powershell
python scripts\verify_day05_environment.py
```

The command records the exact Git revision, package/command availability,
parser-record contract checks, a real local DVC restore smoke test, a local
MLflow parameter/metric logging smoke test, and the inputs still required for a
full machine-time estimate.

## Contract boundary

The canonical record and final index-sidecar schemas are in
[`data/contracts/`](../../data/contracts/). The existing parser's `id` maps to
the logical `evidence_id` without creating another identity. Parent tables
remain separate from cell records and all source locators/checksums must remain
resolvable. The final index contract is BGE `bge-base-en-v1.5`, 768-dimensional
L2-normalized vectors and exact `faiss.IndexFlatIP`; the current MiniLM/Chroma
artifact is historical and is not accepted as final readiness.

## Capacity gate

The report deliberately records a blocked capacity estimate until a
representative BGE/FAISS, Gemma/Ollama and RAGAS pilot is timed on intended
hardware. The required estimate is:

`(cases * variants * observed seconds per case / 3600) + extraction + captioning + evaluator overhead`

No full evaluation claim is made from package installation or a parser smoke
test. Missing inputs and blockers are retained in the generated JSON report.

## Course/viva explanation

This is reproducible AI engineering and a typed evidence contract: immutable
source hashes and one logical ID prevent a vector or metadata sidecar from
silently changing the fact being cited. A successful DVC restore and MLflow
run are operational checks; the relevant failure case is a missing required
model/pilot input, which remains explicitly blocked rather than becoming a
fabricated readiness result.
