1. WHAT IS AVAILABLE

The app supports source-checked annual filing research for:
  Apple (AAPL): FY2021, FY2022, FY2023, FY2024, FY2025.
  Microsoft (MSFT): FY2021, FY2022, FY2023, FY2024, FY2025.
  Adobe (ADBE): FY2024, ending 2024-11-29.
  NVIDIA (NVDA): FY2024, ending 2024-01-28.
  Salesforce (CRM): FY2024, ending 2024-01-31.
  AMD: FY2024, ending 2024-12-28.
  Intel (INTC): FY2024, ending 2024-12-28.
  Cisco (CSCO): FY2024, ending 2024-07-27.
  Oracle (ORCL): FY2024, ending 2024-05-31.
  IBM: FY2024, ending 2024-12-31, including its incorporated financial exhibit.

There are 18 filings, 10 companies and 15,411 canonical C records. Matched
A/B representations have 5,213/12,077 records. Processing/count coverage meets
the PRD's five Apple/five Microsoft/ten-company requirement. Wider independent
source acceptance is separate and not implied by byte/schema/index checks.

One research request selects one exact filing. Adjacent years printed in that
filing may be compared when both typed source periods exist. Automatic joins
across separate filings/companies are not supported. Use separate cited answers.
The app cannot promise any possible filing question: absent facts, unknown units,
unavailable periods and ambiguous operands must refuse. Live prices, predictions,
quarterly values and investment advice are outside this annual-report scope.

2. SOFTWARE AND PRIVATE CONFIGURATION

Required: Git, Python3.12+ (prepared environment:3.14.2), Node22, project Python dependencies, local Ollama,
llama.cpp llama-server (the exact-model tokenizer), model storage and enough RAM/
disk. The prepared laptop already has its .venv and verified installed assets.
Other team members must install/restore these explicitly; startup does not download.

From the repository root on macOS/Linux:
  python3.12 -m venv .venv
  .venv/bin/python -m pip install -r requirements.txt -r requirements-dev.txt
On Windows use py -3.12 and .venv\Scripts\python.exe. Native launcher defaults
are for Rushil's prepared Mac; Windows executable/model paths must be supplied.
No npm install is required for web/. Optional artifact regeneration uses a
separate document runtime; it is not required to run or demonstrate the app.

The root .env configures the Python model. Never overwrite an existing private file.
  FINRAG_PROVIDER=ollama
  FINRAG_MODEL=gemma3:4b
  FINRAG_MODEL_DIGEST=<the exact digest from configs/gemma3-4b.json>
  OLLAMA_BASE_URL=http://127.0.0.1:11434
Other root paths/settings are documented in .env.example and configs/config.yaml.
Gemini is an explicit optional provider, not the final matched runtime or fallback.

web/.env configures the gateway (server-only settings):
  FINRAG_BACKEND_URL=http://127.0.0.1:8000 (local only; production uses HTTPS)
  FINRAG_BACKEND_TOKEN=<must match the Python FINRAG_API_TOKEN>
  FINRAG_ALLOW_LOOPBACK_HTTP=true (development only)
  FINRAG_BACKEND_TIMEOUT_MS=240000
  SUPABASE_URL=<existing authorized project URL>
  SUPABASE_PUBLISHABLE_KEY=<existing publishable key, never service_role>
  SUPABASE_PASSWORD_AUTH_READY=true
  SUPABASE_AUTH_READY=false (legacy magic-link readiness is separate)
Node loads this ignored file explicitly. Do not paste values into chat, screenshots,
Git, reports, a professor's shared deck or the demonstration JSON export.

The launcher securely creates/reuses output/nov17/local-service.json with owner-only
permissions. This holds the local API credential. Keep it private. Vercel needs the
same backend credential and approved HTTPS backend origin as server environment
settings. Do not expose raw Ollama or tokenizer services publicly.

4. DATABASE AND SAVED QUESTIONS

The existing FinRAG Supabase project is already provisioned and its private
saved_queries schema/policies are applied. The cloud database needs no local
Postgres start command. Keep its URL/publishable key in web/.env and Vercel.
On a genuinely new authorized project, inspect tables first, apply
supabase/schema.sql once, run supabase/verify_rls.sql and security advisors.
Do not rerun CREATE TABLE blindly on the existing project. Owner-only select,
insert and delete are required; anonymous access is forbidden.

In the app choose Your workspace, enter email and password, then Sign in.
For a new account choose Create account and confirm the actual email. Passwords
must meet the form's12-character minimum. Configure the exact hosted origin in
Supabase Auth Site URL/redirects. Default email restrictions may require the owner
to configure SMTP or permitted recipients. No automated test establishes actual
new-user email delivery. Do not disable confirmation to make a demo appear ready.
The original confirmation-link field accepts only this project's allowlisted link.

Ask a question, choose Save question, then open Saved Questions. Refresh in the
same tab and reopen Saved Questions: the server retrieves the same Supabase row.
Choose it to restore its question, selected filing and period. Delete it, refresh,
and verify it stays deleted. Use More questions/Previous questions for pages.
Saved questions are private input records, not approved model answers or gold.

Only an access token is held in sessionStorage. Page refresh retains it in the
same tab; signing out, closing the tab or expiry may require signing in again.
This does not delete saved rows. The API checks the current user on every request;
expired sessions clear the signed-in label. No refresh token/service-role key is
stored in browser storage. Two approved synthetic accounts previously passed actual
local/production sign-in and owner-isolation tests and were then deleted.

Known numerical questions use the explicitly identified typed-calculator route:
the original source values, licensed expression and exact Decimal result are the
answer, with no optional model-written explanation. This avoids losing a valid
calculation to a prose-generation timeout. Narrative answers still use the pinned
model. Matched A-G defaults remain unchanged and cannot reuse interactive timing
as controlled-experiment evidence. Unknown programs may still require a real
model proposal; missing/ambiguous premises must refuse.

5. FILING PREPARATION AND SELECTION

The data/application_filings.json registry lists exact issuer/accession/form/period
and original source URLs. Pinned source snapshots are in data/source/corpus/;
data/corpus_html_profiles.json declares supported layouts and hashes.
Generated canonical packages and matched indexes live in output/nov17/corpus/.
They are ignored build assets, not uploaded user files. There is no general PDF
upload feature: an unprocessed arbitrary filing cannot be advertised as supported.

Check processing before the demo:
  .venv/bin/python scripts/check_project_readiness.py --publish-web
Expect18checked/18connected-source-packages,10companies, AAPL5/MSFT5, and the
matched index counts listed above. The script validates original source/exhibit
hashes, registry/package/schema identities and reopened native index records.
It updates web/data/filings.json and project-status.json from actual checked assets.
Changing those files requires restarting Node or redeploying the frontend.

For a clean restore, obtain the verified generated package/cache/model backup from
the project owner, preserving paths/hashes. To rebuild packages explicitly:
  .venv/bin/python scripts/prepare_evidence.py --output data/processed/nov04
  .venv/bin/python scripts/verify_canonical_data.py --package data/processed/nov04 \
    --output output/nov17/canonical_audit.json --artifacts-dir output/restore-check
  .venv/bin/python scripts/build_corpus_candidates.py --build \
    --package data/processed/nov04 --audit output/nov17/canonical_audit.json \
    --output output/nov17/corpus --model-cache output/models-http
These require installed parser/index dependencies and pinned BGE assets; the source
archives are already committed. Use a new output directory for changed inputs;
immutable generations must not be overwritten to bypass source validation.
Original PDF extraction additionally needs the declared exact rendition files.

To add a NEW filing, a member must obtain the public original source, verify the
exact issuer/accession/year, add its registry/profile and supported layout, parse
typed cells/narratives with tests, build/reopen its indexes, and run source checks.
An inventory entry by itself stays unavailable. Do not invent units/periods or
replace an accepted package with a different rendition under the same identity.

In the website choose Research > company > filing. Period end defaults to that
filing's fiscal year. For annual totals leave Fiscal-year total selected; choose
Year-end balance only for supported instant balance-sheet values. Changing any
selection/question clears the old answer. Filings distinguishes available research,
processed-but-disconnected and processing-required entries. Connection and coverage
separates current connectivity from independent source/experiment acceptance.

9. COMMON ERRORS

"ModuleNotFoundError: requests/faiss/...": use the project's .venv executable;
system Python is not the installed project environment.
"Port occupied": inspect the owning process/working directory; reuse a healthy
FinRAG service. Do not kill an unrelated listener or launch duplicate model servers.
"Model digest/GGUF mismatch": restore the pinned assets; a new model is a changed
configuration, not permission to bypass identity checks.
"Source/package changed": restore exact hashed bytes or rebuild into a new reviewed
generation. Do not edit hashes to silence the failure.
Only Apple appears: refresh the deployed frontend, inspect /api/filings and
/api/health, run check_project_readiness.py, and restart/redeploy the reviewed
gateway. There should be18registry entries; runtime connectivity is separate.
"Service unavailable": check local model/tokenizer/API status first, then tunnel
and Vercel backend URL/token. A hosted UI alone is not an answering backend.
"Sign-in expired": sign in again; saved Supabase rows remain intact.
No confirmation email: project owner checks Auth logs, permitted recipients,
Site URL/redirects and SMTP. Do not assume email delivery from synthetic tests.
"Insufficient evidence": inspect selected filing, fiscal year, period type and
original source values; change the question or process the missing original facts.
Some tables require horizontal scrolling within the evidence panel.
Chart unavailable/experiment not accepted: complete the real review/dependencies
above; do not open the gate by changing status flags.
